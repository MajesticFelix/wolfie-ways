Stony Brook SPOT Bus API

Unofficial reverse-engineered documentation for the EtaSpot transit API powering Stony Brook University's campus bus tracking system at stonybrook.etaspot.net.

Unofficial REST / JSON No Auth Required

Base URL & Authentication

All endpoints are accessed via a single PHP gateway. Every request requires a token parameter, but the fixed string TESTING works for all public queries — no registration needed.

Base URL
https://stonybrook.etaspot.net/service.php

Common Query Parameters

ParamTypeRequiredDescription
service string Required The API method name (e.g. get_routes)
token string Required Authentication token. Use TESTING.
Example Request
GET https://stonybrook.etaspot.net/service.php?service=get_routes&token=TESTING
⚠ This is an undocumented API. It may change or break without notice. Use responsibly and avoid excessive polling.

get_routes

Returns all configured bus routes, including their ordered stop lists, display colors, and encoded polylines for map rendering.

GET /service.php?service=get_routes&token=TESTING

No additional parameters required.

Response — get_routes[]

FieldTypeDescription
idintUnique route identifier
namestringFull display name (e.g. "Outer Loop")
abbrstringShort abbreviation (e.g. "Outer")
stopsint[]Ordered array of stop IDs along the route
vTypestringVehicle type (always "Bus")
encLinestringGoogle Maps encoded polyline of the route path
colorstringHex color code for map display
typestringRoute type (e.g. "Loop")
orderintDisplay sort order
showDirectionboolWhether to show direction labels
showPlatformboolWhether to show platform info
showScheduleNumberintFlag for schedule number display
useCustomShapeintWhether route uses a custom map shape
showVehicleCapacityboolWhether to display vehicle capacity in UI

get_stops

Returns all bus stops across all routes, including GPS coordinates. A single stop (e.g. "SAC") may appear multiple times — once per route it belongs to — with a different rid and rsid each time.

GET /service.php?service=get_stops&token=TESTING

Response — get_stops[]

FieldTypeDescription
idintGlobal stop identifier (shared across routes)
ridintRoute ID this stop instance belongs to
rsidintRoute-stop composite ID (unique per route×stop combination)
namestringFull display name (e.g. "Life Science West")
shortNamestringAbbreviated name (e.g. "LifeW")
latfloatLatitude
lngfloatLongitude
extIDstringExternal ID (typically mirrors id as a string)
Example Response
{
  "get_stops": [
    {
      "rid": 1,
      "rsid": 65537,
      "id": 1,
      "name": "SAC",
      "lat": 40.91435,
      "lng": -73.12485,
      "extID": "1",
      "shortName": "SAC"
    }
  ]
}
💡 To get unique stops, deduplicate by id. The rid field tells you which route each stop-instance is associated with.

get_patterns

Returns all route patterns — specific path variants that buses follow. A single route (like "Outer Loop") can have multiple patterns representing different service windows (e.g. morning pull-in, full loop, late night).

GET /service.php?service=get_patterns&token=TESTING

Response — get_patterns[]

FieldTypeDescription
idintUnique pattern ID
namestringInternal pattern name (e.g. "I/L 1-A 7am-10:00pm")
typeintPattern type: 1 = pull (partial), 2 = full service, 4 = full service (alternate)
lengthfloatRoute length in miles
colorstringHex color for map rendering
encLinestringGoogle Maps encoded polyline of this pattern's path
decLinearrayDecoded line data (typically empty)
routesint[]Array of route IDs this pattern belongs to
routeNamesstring[]Human-readable route names
stationsarrayStation data (typically empty)
stopIDsint[]Ordered stop IDs for this pattern (may include the start stop repeated at the end for loops)
extIDstring|nullExternal identifier
Example Response (truncated)
{
  "get_patterns": [
    {
      "id": 46,
      "name": "I/L 1-A 7am-10:00pm",
      "type": 2,
      "length": 1.615,
      "color": "#E89C3C",
      "encLine": "uavxFlei}L...",
      "routes": [1],
      "routeNames": ["Inner Loop"],
      "stopIDs": [1, 2, 3, 4, 5, 6, 7, 8, 1]
    }
  ]
}

get_active_patterns

Returns only the patterns that are currently running. When no buses are in service, the result object is empty. The client polls this periodically to detect route configuration changes.

GET /service.php?service=get_active_patterns&token=TESTING

Response

Example (no active service)
{
  "get_active_patterns": {
    "errors": [],
    "result": {}
  }
}
ℹ When buses are running, result will contain pattern IDs mapped to their active configurations. Polled every ~30 seconds by the web client alongside get_version_id.

get_stop_etas

Returns estimated arrival times at one or all stops. Each ETA entry represents an upcoming scheduled or predicted bus arrival. This is the primary endpoint for "when is my bus coming?" queries.

GET /service.php?service=get_stop_etas&token=TESTING

Optional Parameters

ParamTypeDefaultDescription
stopID int all Filter to a specific stop. Omit to get ETAs for all stops.
statusData int 0 Set to 1 to include schedule status info

Response — get_stop_etas[]

Array of objects, one per stop. Each contains an enRoute array of upcoming arrivals:

FieldTypeDescription
idint|stringStop ID
enRoute[].minutesintMinutes until arrival
enRoute[].timestringPredicted arrival time (e.g. "08:32AM")
enRoute[].schedulestringScheduled arrival time
enRoute[].statusstringSchedule status ("-" = no live data, otherwise early/late info)
enRoute[].routeIDintWhich route this arrival is on
enRoute[].scheduleNumberstringSchedule block identifier
enRoute[].stopIDintStop ID (redundant with parent)
enRoute[].patternStopIDintPattern-stop composite ID
enRoute[].timePointint1 if this is a scheduled timepoint
enRoute[].trackintTrack/platform number
enRoute[].directionstringDirection label (e.g. "Outbound")
enRoute[].directionAbbrstringDirection abbreviation (e.g. "O")
enRoute[].equipmentIDstringAssigned bus number ("-" = schedule-based, not live)
Example — Single Stop
GET /service.php?service=get_stop_etas&stopID=17&statusData=1&token=TESTING

{

    {
      "id": "17",
      "enRoute": [
        {
          "minutes": 462,
          "routeID": 3,
          "time": "08:32AM",
          "schedule": "08:32AM",
          "status": "-",
          "direction": "Outbound",
          "equipmentID": "-"
        }
      ]
    }
  ]
}

GET /service.php?service=get_schedules&stopID={id}&token=TESTING

includeETAData int 0 Set to 1 to merge live ETA data
orderedETAArray int 0 Set to 1 to sort results by time

runIDintUnique run identifier

get_version_id

Returns a version number that increments when route/pattern configuration changes. The client polls this to know when to re-fetch static data like routes, stops, and patterns.

GET /service.php?service=get_version_id&token=TESTING
Response
{
  "versionID": 77
}
💡 Cache your routes/stops/patterns data and only re-fetch when versionID changes. The web client checks this every ~30 seconds.

Polling Strategy

Based on observed request patterns from the official web client, here's how the frontend polls the API:

EndpointFrequencyTrigger
get_vehicles (with ETA flags)~10 secondsContinuous while page is open
get_service_announcements~10 secondsContinuous while page is open
get_stop_etas (specific stop)~10 secondsWhile a stop info panel is open
get_version_id~30 secondsContinuous — triggers route refresh on change
get_active_patterns~30 secondsPolled alongside version check
get_routes, get_stops, get_patternsOnceOn page load, re-fetched on version change
get_stopimagesOnceOn page load
get_schedulesOn demandWhen user clicks a stop
⚠ Be respectful with polling. The official client uses ~10s intervals for live data. For personal projects, consider 15–30 second intervals to reduce server load.

Recommended Client Architecture

On startup, fetch get_routes, get_stops, get_patterns, get_stopimages, and get_version_id once and cache them. Then poll get_vehicles (with includeETAData=1&inService=1&orderedETAArray=1) every 15 seconds for live bus positions. Periodically check get_version_id and re-fetch the cached data only when the version changes. Use get_stop_etas and get_schedules on demand when a user selects a stop.
